A future is an interface which the concrete completable future class implements.

The completable future specifically extends future's capabilities to support aysnchronous processing. Officially the java API states: A completable future is a future that may be explicitly completed (by setting its value and status), and may be used as a Completion stage, supporting dependent functions and actions that trigger upon its completion. The key words here are completion stage and actions that get triggered. If you're familiar with promises and callbacks in java script or other languages, you'll have some idea about what a completable future is and how it works.

It's a promise of a future result, so in the case of send async on HTTP client, it would be a future HTTP request response. You can use specific methods on completable future to execute code at certain lifecycle stages. In other words, there are methods on the completable future that support callbacks. A callback is a general programming concept, which describes passing a function as an argument to another function. This gets called later, in the future, when a specific event occurs.

Significantly the calling function doesn't wait around for the callback to be executed. You've seen how lambda expressions don't get executed, if they're used as method arguments, until the method is invoked. Similarly callbacks don't get executed until a certain stage or triggering event occurs. It's yet another level of deferred execution of a stored function, if that makes sense. These special types of methods (which take callbacks as arguments), wait until a certain event is triggered.

Java doesn't actually use the term call back in its own API documentation, but I'll be using this term to help you identify this behavior.
