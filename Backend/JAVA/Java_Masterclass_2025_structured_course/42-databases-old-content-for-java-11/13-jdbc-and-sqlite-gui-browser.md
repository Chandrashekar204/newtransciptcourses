So we've seen how to work with a SQLite database from the command line. Now we're going to learn how to use a database from a java application. And to do so, we're going to be using the JDBC API. Now JDBC stands for java database connectivity. So using JDBC, we can not only work with databases, but also spreadsheets and flat files. So think of JDBC as a middleman that sits between a java application and a data source. To use a particular data source from an application, we need the JDBC driver for the data source.

For example, to access a SQLite database from an application, we need a SQLite JDBC driver. Now the driver is simply a java library containing classes that implement the JDBC API. Now because all JDBC drivers have to implement the same interfaces, it's not difficult to change the data source and application users. For example, if an application uses a SQLite database and then we decide later that we want to use a MySQL database, all we have to do is use the MySQL JDBC driver instead of the SQLite one in addition to of course migrating the data to a MySQL database.

Now in reality, unfortunately, it's not that simple. Nothing is ever 100 portable. But if we write our JDBC code with thought in mind that we may have to change the data source later, we can make our lives easier by avoiding the use of database specific SQL code and also behaviors wherever possible. If we wanted to work with a spreadsheet or a flat file that's fine as long as there's a JDBC driver that works with that spreadsheet or file format.

And if you're feeling particularly a game, you can always write the JDBC driver yourself if necessary.
