# Introduction to the Author and the Course

*Section: Setting the stage*

Thank you for joining my course on Rest APIs. My name is Rajiv Sakhuja. You may call me Raj. Here is my quick intro. I have been working in IT industry for over 20 years now. In the last ten years I have worked as a consultant to assist a number of small to large enterprises, build software systems by leveraging emerging technologies. Last five years or so, I have focused on helping organizations with their digital strategy, where APIs have always played a central role.

The content in this course reflect my learnings from these experiences. I hope you will enjoy learning from this course. As much as I enjoyed building this course in this introductory lecture, I'll provide you the course outline and go over some tips that will help you get the most out of this course. Let's go through the course outline. The course is divided into six parts. In the part one, you will learn the fundamentals of APIs, how the rest APIs have evolved, how rest APIs are different from plain old XML or soap services.

You'll also learn about the API value chain, wherein I'll talk about the various stakeholders that participate in the creation of Rest APIs. In Part two, I'll cover the rest API design principles and best practices. Once you will have a good understanding of these design principles and practices, you will be ready to build the rest APIs. You may build your APIs from scratch, but a better way to build software is to use common patterns.

So in part three, you will learn common patterns for building features in rest APIs. API security is one of the biggest concerns, so I'll cover Rest API security in details in part four. In Part five, I'll cover processes and practices for building rest APIs. I will also cover Swagger specifications. Once your APIs are built, you need to think about how you're going to manage these APIs. Do you need an API management platform?

If you do need an API management platform, what kind of features would you need for your APIs? These are the kind of questions that you should be able to answer after going through Part six in this course, which is on API management. One important thing to note here is that I have gathered the design patterns and best practices by going through the details of hundreds of APIs. These and many other organizations have an API first culture.

They are putting in a lot of investment in building their APIs as you will do your own research. It is very much possible that you may come across newer patterns. If that is the case, I would truly appreciate if you could reach out to me and share those patterns with me. My intent is to ensure that this course covers as many patterns as possible. Next, I'll share some tips for getting the most out of this course as I'll go through this course.

Keep in mind your own organization. Can your organization benefit by building APIs? Who are the stakeholders in your organization's API ecosystem? Think about how you would use the design patterns that you will learn in building your own APIs for your organization. As I'll walk you through the example APIs, I suggest that you spend some time going through the documentation for those example APIs. Get your hands dirty.

That is code. You don't have to code in NodeJS, which is what I am using. Use your favorite language to code your APIs. This will give you a better feel of how rest APIs work under the cover. Last but not the least, continue to explore APIs built by other organizations and continue to learn new skills and patterns for rest APIs.
