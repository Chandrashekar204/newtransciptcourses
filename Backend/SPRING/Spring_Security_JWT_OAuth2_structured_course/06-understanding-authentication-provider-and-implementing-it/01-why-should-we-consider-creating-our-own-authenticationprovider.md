But there will be some scenarios where you may have your own custom authentication requirements. For example, think like you have a requirement to allow the authentication of an user only if the user age is greater than 18, or you may have some custom requirement where you want to allow the authentication only from certain countries.

To accommodate these kind of requirements, you need to define your own AuthenticationProvider implementation. And inside your own AuthenticationProvider implementation, once the user details are loaded from your UserDetailsService, you can perform the additional checks like age check or country check, or any other custom checks. Once you are satisfied with these additional checks of authentication, you can create an Authentication object representing either a successful authentication or a failure authentication inside your own Authentication Provider.

Once your own Authentication Provider returns authentication object, the ProviderManager is going to take care of sending back the details to the filters, and from the filters it will go back to the end user.
