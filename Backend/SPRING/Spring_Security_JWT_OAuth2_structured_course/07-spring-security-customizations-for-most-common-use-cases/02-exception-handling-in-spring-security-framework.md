In general, the Spring Security framework, it is not going to worry about all kind of business exceptions or all kind of runtime exceptions that are going to happen inside your application core. It is only going to worry and handle security related exceptions. So inside that security framework, there are two types of exceptions that may happen. The very first type of exception is AuthenticationException, which may result into the 401 status. 401 indicates that the person or the client application is not authenticated.

So all the exceptions like BadCredentialsException, UsernameNotFoundException, they all come under the category of AuthenticationException. Just like how we have 401, we also have 403 error inside HTTP status codes. 403 indicates forbidden error. That means the person or the client application is properly authenticated but they don't have enough privileges or roles to access a secured API. So in all these kind of scenarios, we are going to get the 403 error and all the exceptions related to 403, they come under the AccessDeniedException.

Basically Spring Security is going to worry on how to handle only these two type of exceptions. Inside Spring Security we have a filter which is going to monitor these two exceptions. So this filter name is ExceptionTranslationFilter. The responsibility of this filter is first it is going to check what is the type of exception received? If it is related to the AuthenticationException, it is going to invoke the AuthenticationEntryPoint related implementations.

So AuthenticationEntryPoint is an interface inside the Spring Security framework, which is responsible to handle all authentication related exceptions. By default, Spring Security provide lot many AuthenticationEntryPoint implementations. So based upon the scenario on the flow, this ExceptionTranslationFilter, it is going to invoke one of the AuthenticationEntryPoint implementation classes. Similarly, in the scenarios where the exception type is AccessDeniedException, then the responsibility of the ExceptionTranslationFilter is to invoke one of the implementation of AccessDeniedHandler interface.

With this, I'm assuming you got some clarity how to build our own custom logic, our custom response that needs to be sent in the scenario of AuthenticationException, and in the scenario of AccessDeniedException. We just have to override these two interfaces and write our own logic to send our own custom response or to execute our own custom logic.
