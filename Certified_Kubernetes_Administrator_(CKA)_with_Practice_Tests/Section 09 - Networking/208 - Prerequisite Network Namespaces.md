1 In this video, we get introduced 2 to network namespaces in Linux. 3 Network namespaces are used by containers like Docker 4 to implement network isolation. 5 We'll start with a simple host. 6 As we know already, containers are separated 7 from the underlying host using namespaces. 8 So what are namespaces? 9 If your host was your house, 10 then namespaces are the rooms within the house 11 that you assign to each of your children.

12 The room helps in providing privacy to each child. 13 Each child can only see what's within his or her room. 14 They cannot see what happens outside their room. 15 As far as they're concerned, 16 they're the only person living in the house. 17 However, as a parent, 18 you have visibility into all the rooms in the house, 19 as well as other areas of the house. 20 If you wish, you can establish connectivity 21 between two rooms in the house.

22 When you create a container, you wanna make sure 23 that it is isolated, 24 that it does not see any other processes 25 on the host or any other containers. 26 So we create a special room for it on our host 27 using a namespace. 28 As far as the container is concerned, 29 it only sees the processes run by it 30 and thinks that it is on its own host. 31 The underlying host, however, has visibility 32 into all of the processes, 33 including those running inside the containers.

34 This can be seen when you list the processes 35 from within the container. 36 You see a single process with a process ID of one. 37 When you list the same processes 38 as a route user from the underlying host, 39 you see all the other processes 40 along with the process running inside the container. 41 This time with a different process ID. 42 It's the same process running with different process IDs 43 inside and outside the container.

44 That's how namespaces work. 45 When it comes to networking, our host has its own interfaces 46 that connect to the local area network. 47 Our host has its own routing and arp tables 48 with information about rest of the network. 49 We want to seal all of those details from the container. 50 When the container is created, 51 we create a network namespace for it. 52 That way, it has no visibility 53 to any network related information on the host.

54 Within its namespace, 55 the container can have its own virtual interfaces, 56 routing, and arp tables. 57 The container has its own interface. 58 To create a new network namespace on a Linux host, 59 run the IP netns add command. 60 In this case, we create two network namespaces 61 to list the network namespace, run the IP netns command. 62 To list the interfaces on my host, 63 I run the IP link command.

84 The same is true with the arp table. 85 If you run the arp command on the host, 86 you see a list of entries. 87 But if you run it inside the container, you see no entries 88 and the same for routing table. 89 Now, as of now, these network namespaces 90 have no network connectivity. 91 They have no interfaces of their own 92 and they cannot see the underlying host network. 93 Let's first look at establishing connectivity 94 between the namespaces themselves.
