# Static Pods

*Section: Scheduling*

1 In this lecture, 2 we discuss about static pods in Kubernetes. 3 Earlier in this course, we talked about the architecture 4 and how the kubelet functions 5 as one of the many control plane components in Kubernetes. 6 The kubelet relies on the Kube API server 7 for instructions on what pods to load on its node, 8 which was based on a decision made by the kube-scheduler, 9 which was stored in the etcd data store.

10 What if there was no Kube API server and kube-scheduler 11 and no controllers and no etcd cluster? 12 What if there was no master at all? 13 What if there were no other nodes? 14 What if you're all alone in the sea by yourself, 15 not part of any cluster? 16 Is there anything that the kubelet can do 17 as the captain on the ship? 18 Can it operate as an independent node? 19 If so, who would provide the instructions 20 required to create those pods?

21 Well, the kubelet can manage a node independently. 22 On the ship, host, 23 we have the kubelet installed, 24 and of course we have container D as well to run containers. 25 There is no Kubernetes cluster, 26 so there are no Kube API server or anything like that. 27 The one thing that the kubelet knows to do is create pods, 28 but we don't have an API server here to provide pod details. 29 By now, we know that to create a pod, 30 you need the details of the pod in a pod definition file.

31 But how do you provide the pod definition file 32 to the kubelet without a Kube API server? 33 You can configure the kubelet 34 to read the pod definition files 35 from a directory on the server 36 designated to store information about pods. 37 Place the pod definition files in this directory. 38 The kubelet periodically checks this directory for files, 39 reads these files, and creates pods on the host.

40 Not only does it create the pod, 41 it can ensure that the pod stays alive. 42 If the application crashes, 43 the kubelet attempts to restart it. 44 If you make a change 45 to any of the file within this directory, 46 the kubelet recreates the pod 47 for those changes to take effect. 48 If you remove a file from this directory, 49 the pod is deleted automatically. 50 So these pods that are created by the kubelet on its own 51 without the intervention from the API server 52 or rest of the Kubernetes cluster components 53 are known as static pods.

54 Remember, you can only create pods this way. 55 You cannot create replica sets or deployments or services 56 by placing a definition file in the designated directory. 57 They're all concepts 58 part of the whole Kubernetes architecture 59 that requires other cluster plane components 60 like the replication and deployment controllers, et cetera. 61 The kubelet works at a pod level 62 and can only understand pods, 63 which is why it is able to create static pods this way.

64 So what is that designated folder 65 and how do you configure it? 66 It could be any directory on the host 67 and the location of that directory 68 is passed in to the kubelet as an option 69 while running the service. 70 The option is named pod-manifest-path, 71 and here it is set to etc/kubernetes/manifests folder. 72 There's also another way to configure this. 73 Instead of specifying the option 74 directly in the kubelet.service file, 75 you could provide a pod 76 to another config file using the config option 77 and define the directory pod 78 as staticPodPath in that file.

79 Clusters set up by the Kube admin tool uses this approach. 80 If you're inspecting an existing cluster, 81 you should inspect this option of the kubelet 82 to identify the path to the directory. 83 You will then know where to place the definition file 84 for your static pods. 85 So keep this in mind when you go through the labs. 86 You should know to view and configure this option 87 irrespective of the method used to set up the cluster.

88 First, check the option pod-manifest-path 89 in the kubelet service file. 90 If it's not there, then look for the config option 91 and identify the file used as the config file. 92 And then within the config file, 93 look for the staticPodPath option. 94 Either of these should give you the right path. 95 Once the static pods are created, 96 you can view them by running the docker ps command. 97 So why not the kubectl command 98 as we've been doing so far?

99 Remember, we don't have the rest 100 of the Kubernetes cluster yet. 101 So the kubectl utility works with the Kube API server. 102 Since we don't have an API server now, 103 no Kube control utility, 104 which is why we are using the Docker command. 105 So then how does it work when the node is part of a cluster? 106 When there is an API server 107 requesting the kubelet to create pods, 108 can the kubelet create both kinds of pods at the same time?

109 Well, the way the kubelet works is it can take in requests 110 for creating pods from different inputs. 111 The first is through the pod definition files 112 from the static pods folder, as we just saw. 113 The second is through an HTTP API endpoint, 114 and that is how the Kube API server 115 provides input to kubelet. 116 The kubelet can create both kinds of pods, 117 the static pods 118 and the ones from the API server at the same time.

119 Well, in that case, is the API server 120 aware of the static pods created by the kubelet? 121 Yes, it is. 122 If you run the kubectl get pods command 123 on the master node, 124 the static pods will be listed as any other pod. 125 Well, how is that happening? 126 When the kubelet creates a static pod, 127 if it is a part of a cluster, 128 it also creates a mirror object 129 in the Kube API server.

130 What you see from the Kube API server 131 is just a read-only mirror of the pod. 132 You can view details about the pod, 133 but you cannot edit or delete it like the usual pods. 134 You can only delete them 135 by modifying the files from the node's manifest folder. 136 Note that the name of the pod 137 is automatically appended with the node name, 138 in this case, node01. 139 So then why would you want to use static pods?

140 Since static pods are not dependent 141 on the Kubernetes control plane, 142 you can use static pods 143 to deploy the control plane component itself 144 as pods on a node. 145 Well, start by installing kubelet on all the master nodes, 146 then create pod definition files that uses Docker images 147 of the various control plane components, 148 such as the API server, controller, etcd, et cetera, 149 place the definition files 150 in the designated manifest folder, 151 and the kubelet takes care 152 of deploying the control plane components themselves 153 as pods on the cluster.

154 This way, you don't have to download the binaries, 155 configure services, or worry about the services crashing. 156 If any of these services were to crash, 157 since it's a static pod, 158 it will automatically be restarted by the kubelet, 159 neat and simple. 160 That's how the Kube admin tool sets up a Kubernetes cluster, 161 which is why when you list the pods 162 in the kube-system namespace, 163 you see the control plane components 164 as pods in a cluster set up by the Kube admin tool.

165 We will explore that setup in the upcoming practice test. 166 Before I let you go, one question that I get often 167 is about the difference between static pods and DaemonSets. 168 DaemonSets, as we saw earlier, 169 are used to ensure one instance 170 of an application is available on all nodes in the cluster. 171 It is handled by a DaemonSet controller 172 through the Kube API server, whereas static pods, 173 as we saw in this lecture, 174 are created directly by the kubelet 175 without any interference from the Kube API server 176 or rest of the Kubernetes control plane components.

177 Static pods can be used 178 to deploy the Kubernetes control plane components itself. 179 Static pods are created directly by the Kubelet 180 and are not scheduled by the kube-scheduler. 181 Pods created by DaemonSets 182 are scheduled by the default scheduler using NodeAffinity. 183 Well, that's it for this lecture. 184 Head over to the practice test 185 and practice working with static pods.
