95 If you were to list the running containers, 96 you wouldn't see the container running. 97 If you list all containers, including those that are stopped, 98 you will see that the new container you ran 99 is in an exited state. 100 Now, why is that? 101 Unlike virtual machines, 102 containers are not meant to host an operating system. 103 Containers are meant to run a specific task or process, 104 such as to host an instance of a web server 105 or an application server or a database, 106 or simply to carry out some kind of computation 107 or analysis task.

108 Once the task is complete, the container exits. 109 A container only lives 110 as long as the process inside it is alive. 111 If the web service inside the container is stopped or crashed, 112 then the container exits. 113 This is why when you run a container from an Ubuntu image, 114 it stops immediately, 115 because Ubuntu is just an image of an operating system 116 that is used as the base image for other applications.

117 There is no process or application running in it by default. 118 If the image isn't running any service, 119 as is the case with Ubuntu, 120 you could instruct Docker to run a process 121 with the docker run command. 122 For example, a sleep command 123 with a duration of five seconds. 124 When the container starts, 125 it runs the sleep command 126 and goes into sleep for five seconds, 127 after which the sleep command exits 128 and the container stops.
