# Docker on Windows

*Section: Docker on Mac & Windows*

1 Earlier in this course, we learned that containers share the underlying OS kernel. 2 As a result, you cannot have a Windows container running on a Linux host or vice versa. Keep this 3 in mind throughout this lesson. It's an important concept, and most beginners tend to trip over it. 4 So what are the options for Docker on Windows? Historically, there were two, 5 the older Docker toolbox approach and the modern Docker desktop for Windows. The modern path has 6 come a long way. So let's start with the legacy option just to understand where this came from, 7 then move to what you should actually use today. Docker toolbox was the original support for 8 Docker on Windows. Imagine you have a Windows laptop and no access to any Linux system, 9 but you'd like to try Docker. What would you do? You'd install virtualization software like Oracle 10 VirtualBox or VMware Workstation, deploy a Linux VM such as Ubuntu or Debian, then install Docker 11 on that Linux VM and play around with it. That's all Toolbox really did. It bundled VirtualBox, 12 the Docker engine, Docker machine, Docker Compose, and a UI called Kitematic into one installer 13 and shipped a lightweight VM called boot2docker with Docker pre-installed. Easy onboarding, but 14 it didn't really have anything to do with Windows. You couldn't create Windows-based images or run 15 Windows containers, you were just running Docker on a Linux VM that happened to live on a Windows 16 host. Toolbox is now deprecated, it stopped being maintained back in 2020. If you're on Windows 10 17 or Windows 11, any edition, including home, you should use Docker Desktop instead. If you're stuck 18 on Windows 7, you have bigger problems than Docker. Microsoft ended Windows 7 support in January 2020.

19 Docker Desktop for Windows is the modern option and it's what nearly everyone should use today. 20 Like the toolbox approach, Docker Desktop still creates a small Linux environment under the hood 21 because remember, containers share the host kernel and Windows isn't Linux. The big difference is 22 how that Linux environment is created. Docker Desktop on Windows supports two backends for 23 running Linux containers. The default and the one you should use is WSL2, the Windows subsystem for 24 Linux version 2. WSL2 runs a real Linux kernel inside Windows. Docker Desktop runs the daemon 25 inside a WSL2 distribution so containers get native Linux kernel performance, fast file system 26 operations, and low memory use. WSL2 has been the default backend since Docker Desktop 2.3 27 released back in March 2020. It works on Windows 10 and Windows 11, including home editions, which 28 was the the big unlock because home editions don't have Hyper-V. The second backend is Hyper-V, 29 Microsoft's native hypervisor. This is the older path, it boots a full Linux virtual machine and 30 runs Docker inside it. It only works on Pro, Enterprise, and Education editions of Windows 31 because home editions don't ship with Hyper-V. Most people don't need this anymore. Use it only 32 if you have a specific reason, say an environment that requires Hyper-V and prohibits WSL2.

33 Docker Desktop for Windows runs on Windows 11, Home, Pro, Enterprise, Education, and Windows 10, 34 same editions, as long as Microsoft still supports that Windows release. One important thing, 35 Docker Desktop is not supported on Windows Server. Windows Server is a different product with a 36 different install path. For Windows Server 2019, 2022, or 2025, you install the Docker engine 37 directly or use Mirantis Container Runtime, which is the commercial successor to what used to be 38 called Docker EE for Windows Server. Docker Desktop is a developer workstation product. For 39 production servers, use the engine-only install. Here's the most important point. Everything we've 40 been discussing so far runs Linux containers, Linux applications, packaged into Linux Docker 41 images. We're not talking about Windows applications, Windows images, or Windows containers.

42 Both Toolbox and Docker Desktop by default help you run Linux containers on a Windows host. But 43 there's a separate world. With Windows Server 2016, Microsoft announced support for Windows 44 containers for the first time. You can package Windows applications into Windows Docker images 45 and run them on a Windows Docker host using Docker Desktop. When you install Docker Desktop, 46 the default mode is Linux containers. If you want to run Windows containers, you switch modes 47 through the system tray menu, right-click the Docker icon, and pick switch to Windows containers.

48 Unlike in Linux, there are two types of containers in the Windows world. The first is a Windows 49 server container, which works exactly like a Linux container. The OS kernel is shared with 50 the underlying operating system. The second is Hyper-V isolation. To allow a stronger security 51 boundary between containers and to let kernels with different versions and configurations coexist, 52 each Hyper-V isolated container runs inside its own highly optimized virtual machine, 53 guaranteeing complete kernel isolation between the container and the host. In the Linux world, 54 you have base images like Ubuntu, Debian, Fedora, and Alpine. That's what you specify at the top of 55 the Dockerfile. In the Windows world, there are two main base images, Windows Server Core and 56 Nano Server. Nano Server is a headless deployment option that runs at a fraction of the size of the 57 full operating system. Think of it as the Alpine equivalent. Windows Server Core is heavier than 58 you might expect, but it's the full-featured Windows base. Windows containers are supported 59 on Windows Server 2016 and newer on Nano Server and on Windows 10 and Windows 11 Pro and Enterprise 60 editions. Remember though, on Windows 10 and 11 Pro at Enterprise, every Windows container is 61 deployed with Hyper-V isolation. So each container runs on its own optimized VM. There's an old 62 warning that VirtualBox and Hyper-V cannot coexist on the same Windows host. That used to be true. If 63 you started with Docker Toolbox using VirtualBox and wanted to migrate to Hyper-V, you had to pick 64 one or the other. There's a migration guide in Docker's documentation for that exact case. The 65 good news is, this restriction has mostly faded. VirtualBox 6.0, released back in 2018, added 66 Hyper-V coexistence support and the modern WSL2 backend doesn't use Hyper-V at all, so the conflict 67 largely doesn't apply anymore. Worth knowing if you're on an older setup. On modern Windows, 68 in any edition, including Home, Docker Desktop with the WSL2 backend is the answer.
