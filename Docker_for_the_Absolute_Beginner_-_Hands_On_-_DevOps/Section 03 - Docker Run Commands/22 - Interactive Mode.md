# Interactive Mode

*Section: Docker Run Commands*

1 Now let's look at inputs. I have a simple prompt application that, when run, asks for my name. 2 And on entering my name, it prints a welcome message. If I were to dockerize this application 3 and run it as a docker container, it wouldn't wait for the prompt. It just prints whatever 4 the application is supposed to print on standard out. That's because by default, the docker 5 container does not listen to standard input. Even though you're attached to its console, 6 it isn't able to read any input from you. It doesn't have a terminal to read inputs from.

7 It runs in a non-interactive mode. If you'd like to provide your input, you must map the 8 standard input of your host to the docker container using the dash i parameter. The 9 dash i parameter is for interactive mode. And when I input my name, it prints the expected output. 10 But there's something still missing. The prompt. When we ran the app at first, it asked us for 11 our name. But when dockerized, that prompt is missing, even though it seems to have accepted 12 my input. That's because the application prompts on the terminal and we have not attached to the 13 container's terminal. For this, use the dash t option as well. The dash t stands for pseudo 14 terminal. So with the combination of dash i and dash t, we're now attached to the terminal as 15 well as in interactive mode on the container. Now you might be wondering, why would I ever use dash 16 i alone or dash t alone if dash i t is the real combination? Well, they both have honest use cases.

17 They're just narrower. The dash i flag alone is the right choice when I'm piping data into the 18 container. I want standard input connected so the container can read my data. But I don't need a 19 terminal because I'm not typing anything. The classic example is piping a SQL file into a 20 Postgres container. If I tried dash it here, docker would actually refuse because pipes aren't 21 terminals and dash t insists on one. So for any kind of stream in pipeline, dash i alone is exactly 22 what you want. The dash t flag alone is for when I want colored output or progress bars, but I don't 23 need to type anything. Programs check whether they're attached to a terminal to decide whether 24 to emit colors and pretty formatting. With dash t, the program thinks it's talking to a real terminal 25 and gives me the rich output. And without dash i, I skip wiring up the keyboard I'm not actually 26 using. In practice, I reach for dash it most of the time, dash i alone when I'm piping data in.
