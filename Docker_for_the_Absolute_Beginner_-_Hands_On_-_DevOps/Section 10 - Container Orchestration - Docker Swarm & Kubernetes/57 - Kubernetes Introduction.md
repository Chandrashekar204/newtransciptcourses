# Kubernetes Introduction

*Section: Container Orchestration - Docker Swarm & Kubernetes*

1 We will now get a brief introduction to basic Kubernetes concepts. 2 Kubernetes really requires its own course, well, a few courses, at least five, 3 but we will try to get a brief introduction to it here. 4 With Docker, you are able to run a single instance of an application 5 using the Docker CLI by running the docker run command. 6 Running an application has never been so easy. 7 With Kubernetes, using the Kubernetes CLI known as kubectl, 8 you can run a thousand instances of the same application with a single command.

9 The modern way to do this is to create a deployment. 10 kubectl create deployment mywebserver with the image flag set to mywebserver 11 and the replicas flag set to 1000. 12 When you start scaling up like this, watch your resource limits. 13 Kubernetes will happily try to schedule a thousand replicas 14 on a three-node cluster and run into trouble. 15 Kubernetes can scale it up to 2000 with another command.

16 It can be configured to do this automatically 17 so that instances and the infrastructure itself can scale up and down based on user load. 18 Kubernetes can upgrade these 2000 instances of the application 19 in a rolling upgrade fashion, one at a time, with a single command. 20 If something goes wrong, it can help you roll back these images with a single command. 21 Kubernetes can also help you test new features of your application 22 by only upgrading a percentage of these instances through A-B testing methods.

23 Let's take a quick look at the Kubernetes architecture. 24 A Kubernetes cluster consists of a set of nodes. 25 Let us start with nodes. 26 A node is a machine, physical or virtual, 27 on which the Kubernetes software, a set of tools, are installed. 28 A node is a worker machine and that is where containers will be launched by Kubernetes. 29 But what if the node on which the application is running fails?

30 Well, obviously, our application goes down. 31 So you need to have more than one node. 32 A cluster is a set of nodes grouped together. 33 This way, even if one node fails, 34 you have your application still accessible from the other nodes. 35 Now we have a cluster, but who is responsible for managing this cluster? 36 Where is the information about the members of the cluster stored? 37 How are the nodes monitored?

38 When a node fails, how do you move the workload of the failed node to another worker node? 39 That's where the master comes in. 40 The master is a node with the Kubernetes control plane components installed. 41 The master watches over the nodes in the cluster 42 and is responsible for the actual orchestration of containers on the worker nodes. 43 When you install Kubernetes on a system, 44 you're actually installing the following components.

45 An API server, an etcd server, a kubelet service, 46 a container runtime engine like containerd, 47 and a bunch of controllers and the scheduler. 48 The API server acts as the front end for Kubernetes. 49 The users, management devices, and command line interfaces 50 all talk to the API server to interact with the Kubernetes cluster. 51 Next is the etcd key value store. 52 The etcd is a distributed reliable key value store used by Kubernetes 53 to store all data used to manage the cluster.

54 Think of it this way. 55 When you have multiple nodes and multiple masters in your cluster, 56 etcd stores all that information on all the nodes in the cluster in a distributed manner. 57 etcd is responsible for implementing logs within the cluster 58 to make sure there are no conflicts between the masters. 59 The scheduler is responsible for distributing work or containers across multiple nodes.

60 It looks for newly created containers and assigns them to nodes. 61 The controllers are the brain behind orchestration. 62 They're responsible for noticing and responding 63 when nodes, containers, or endpoints go down. 64 The controllers make decisions to bring up new containers in such cases. 65 The container runtime is the underlying software that is used to run containers. 66 Today, that's typically containerd or Creo.

67 And finally, kubelet is the agent that runs on each node in the cluster. 68 The agent is responsible for making sure that 69 the containers are running on the nodes as expected. 70 So what's the relation between Docker and Kubernetes? 71 Kubernetes uses Docker host to host applications in the form of Docker containers, 72 but it need not be Docker all the time. 73 Kubernetes supports alternatives to Docker as well, such as Creo.

74 Modern Kubernetes uses the Container Runtime Interface or CRI 75 to talk to whatever runtime is on each node. 76 The most common runtimes today are containerd and Creo. 77 Docker itself isn't a CRI runtime. 78 It talks to Kubernetes through the CRI, 79 Docker dshim, since direct Docker support was removed in Kubernetes v1.24 80 back in April 2022. 81 Here's the thing that surprises a lot of people.

82 Remember from the engine lesson that Docker uses containerd under the hood. 83 Dockerd hands the real work to containerd and containerd hands it to runc. 84 Kubernetes also uses containerd. It always did. 85 When you ran a container with Docker on a Kubernetes node, 86 kubelet was actually talking to containerd directly, 87 and dockerd was sitting on the side, 88 managing nothing useful from Kubernetes point of view.

89 That's why Kubernetes is dropping Docker. 90 A few years ago, it didn't break anything for running workloads. 91 The runtime stayed the same. 92 Kubernetes just stopped going through the extra dockerd middleman. 93 We also need to learn a little bit about one of the command line utilities 94 known as the kube-command-line-tool, 95 or the kube-control-tool, or kubectl as it is also called. 96 The kube-control-tool is the Kubernetes CLI, 97 which is used to deploy and manage applications on a Kubernetes cluster 98 to get cluster-related information, 99 to get the status of the nodes in the cluster and many other things.

100 A few of the basic commands look like this, 101 kubectl clusterinfo, kubectl getnodes, and kubectl getpods. 102 The clusterinfo command is used to view information about the cluster, 103 and the getnodes command is used to list all the nodes that are part of the cluster. 104 To deploy an application with 100 replicas, 105 you use create-deployment, kubectl create-deployment my-web-app, 106 with the image flag set to my-web-app and the replicas flag set to 100.

107 So to run hundreds of instances of your application across hundreds of nodes, 108 all you need is a single Kubernetes command like this. 109 That's all we have for now. 110 A quick introduction to Kubernetes and its architecture. 111 We now have five-plus courses on Kubernetes on our platform, 112 from beginners to certification courses like CKA, CKAD, CKS, KCNA, and KCSA 113 that can help you become a kubestronaut.
