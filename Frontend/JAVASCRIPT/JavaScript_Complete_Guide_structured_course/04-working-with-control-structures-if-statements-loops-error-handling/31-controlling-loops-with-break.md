> Section 4: Working with Control Structures (if Statements, Loops, Error Handling)

Now to conclude that part about loops, I want to dive into two important keywords which can help you control your loop execution and that's the break and the continue keyword. We saw the break keyword already in our switch statement, there we have break to avoid that fall through mechanism, we can also use break inside of loops to leave the loop execution, to stop the loop execution earlier than it normally would, so to kind of cancel loop execution. How does that work?

Now let's say we only want to output one log entry. Well of course there are various ways of achieving this but one way would be to simply add a break keyword here, maybe after this i++ thing, doesn't really matter for this example though. Now what this will do is it will tell Javascript and it works in any loop by the way, not just in for/of loops but in all loops I showed you, it tells Javascript stop this loop execution of the loop, I'm calling this in.

So if you're calling this in a nested loop, it will stop that nested loop execution but continue with the outside one, which of course means that for the next iteration of the outside one, a new inside one is started and that will then run but the currently running inside nested loop will stop when you call break. If you call break in the outside loop, well then this outside loop is finished and therefore there also will be no next run of the inside loop because that only runs for every iteration of the outside loop and since we break out of that and we finish that outside loop, there is no more inner loop execution too.

So break stops the loop in which you call it, so in which you call it directly, so you have to not have it in a nested loop but directly in that loop as we do it here, this break call here will stop this outer for/of loop. The result of that is that if we save that and we go back to our program and I then attack and have a strong attack and I then click show log, we only see one entry here. We see our attack, we don't see the attack by the monster, we don't see our strong attack or the response on that by the monster, we only see that very first event we wrote to the log, so that very first attack we launched, that's how break works.

Now we could actually use that to make sure that whenever we pressed the show log button, we only output one event at a time but of course not always the same one, that would be great and for that, we can add a new global variable where we keep track of the last event we logged.
