Being able to provide some fallback code here and only execute the code that uses that feature when you need it is a great step in the right direction however and therefore feature detection and fallback code is a great way of using certain features that might be nice to have but are not really essential for your application, which means the rest of your application might work fine even if users can't use this convenience button here because for now in Safari, they would simply get that alert. Checking for feature availability and providing potential fallback code is also viable for features that might be crucial for your application, even if you can't work around it with some fallback code and even if your application really depends on the availability of a certain feature, you can at least use feature detection and fallback code to show the user an error message prompting the user to switch to a different browser for example, even that is better than just failing silently.

Also keep in mind that users of course don't visit the developer tools, so they don't even see the error message in the console and even if they would, it might not tell them anything. So showing at least some error message is better than doing nothing, so even for a vital feature where you can't work around in your fallback code, having such a detection strategy and showing an alert or an error is better than doing nothing.
