# 35.12 — Listening to Events Inside the Component

> Section 35: Bonus: Web Components

We're making progress and we're now able to render some text through our web component. Now still a lot of the logic is missing, for example where we hover over this, we get no event listeners that would do anything but we're getting there step-by-step. Let's now add such event listeners to see how we can quickly add more logic to this component which we then can easily reuse by reusing our custom selector, our custom HTML tag, we want to listen to when we hover over that tooltip icon and then we want to show a tooltip. For this, I will simply add an event listener.

This is a normal DOM element and therefore we can call add event listener and we can listen to the built-in mouse enter event which is fired when the mouse enters this span in this case because I'm attaching it to that tooltip icon span. Then I want to execute a function and for this, I will create a new method which is simply a function inside of a class and I will add this to this class, now I will name this method show tooltip. Now I added this underscore here to kind of make it clear that I only intend on calling this method from inside this class, as you learned earlier in the course Javascript in the past didn't really have private methods and it doesn't even have them right now in all browsers, there is is extra syntax with the hash in front of properties and methods to signal that they should be private but it's in the early stages, it's not supported everywhere, so I'm using this convention which you find in a couple of programs out there where you add an underscore in front of properties or methods which you want to mark as pseudo private so that you only intend on calling these methods from inside the class and therefore even if you name it like this, you can call it from outside too. Now by the way if you're wondering

what I mean with from outside, well since this is now a normal HTML element, you can of course also select it with document query selector and then you can access its properties and call its methods, just like you can do it on any other HTML element. So with an underscore in front of this name though, I'm indicating that this is a method you should not call. You can still do it and we can't stop that but at least we're clear regarding our intention of how this component should be used and if other developers are then using it or we are using it some time in the future after we don't exactly remember how we created it, then we know okay this is a method which should only get called internally which we don't have to care about when we work with our component from outside.

So this show tooltip method is what I want to call, so here I will call this show tooltip and important, I don't add parentheses because I don't want to execute this method here, I only saved a pointer to this method and set this up as my event listener so that when the mouse enter event occurs, then the browser can automatically execute show tooltip. Now inside of show tooltip, I then want to create a tooltip element which I can display. For this I'll create a new constant and I'll name it tooltip container and with documents create element, I'll create a new element of type div, again using one of the built-in HTML elements.

If you have multiple custom elements, you can of course also create those but here I will build an element that only uses primitives, so only use this built-in elements. So I create a div here and in that tooltip container, I can then set a text content of this is the tooltip text which we'll make more generic and settable by the user later and now of course it's all about attaching this container to the DOM and showing it there. So for that, again I will access this, this referring to the tooltip element and now there's just one thing to watch out for, due to the way that this keyword works in Javascript, we need to call bind this here when we point at show tooltip.

This ensures that the this keyword inside of show tooltip always refers to this class. Now here, I can append this child, I can append my tooltip container, the styling will be awful but it should work. If we now save that and we reload the browser, if I now hover over this question mark, indeed we see this is the tooltip text. Now it's not getting removed when I hover away though, you see that when I leave with the mouse it's still there and if I hover over it again, it adds more and more of these texts and that makes a lot of sense because we never remove that when we leave with the mouse.

So I will duplicate my event listener up there and besides mouse enter, I will also add mouse leave here and I will add a new private method, hide tooltip which should in the end remove this tooltip container. Now to access the tooltip container which I create in show tooltip and which therefore is not accessible from inside hide tooltip, I'll turn this from a constant in show tooltip into a property of the whole class. For this in the constructor which is a great place for basic initializations, I'll add a new property by using this keyword and then dot and then the name of the property and that property is basically just like a classwide available variable and I will name that underscore. to also mark that this is only used from inside the class, _tooltipContainer and I will not set an initial value, so it's basically undefined initially but then here in show tooltip, I will store this created div, not in this constant but in this _tooltipContainer and that of course means that the places where I used tooltip container like this also now have to become this _tooltipContainer.

The advantage of this approach is that the newly created div is now stored in a class property and unlike the constant, this property is not just accessible from inside this method but from all the methods in a class. So now in hide tooltip, i can also access this tooltip container and remove that note and for that I will actually access this remove child and I will remove that tooltip container child. Now when we leave this with the mouse, if we don't hover over the question mark anymore, this tooltip container which was added should be removed.

However of course that means that I now also need to hook hide tooltip up as a method that should be executed for mouse leave. Now with that if I save that and we reload this page, now when I hover over the question mark, the tooltip still gets added but if I now leave with the mouse, it's gone and now we have a tooltip that only shows up whilst we hover over the question mark. Now obviously styling is missing and the question mark is still positioned incorrectly but this is another great step forward and we can already see some custom logic doing its job in our web component because you must never forget that this whole hovering logic and so on all happens inside of our web component and that already means that if we copy that and we add another tooltip, so another instance of this element somewhere else, here we go, then there we'll also have this question mark over which we can hover, so we can easily reuse this functionality already.

Now of course it would be nice if we had more styling, more flexibility regarding our tooltip text and so on, so let's work on that tooltip text next because having this generic dummy text here, this is the tooltip text, does not make a lot of sense, the text here should be settable from outside instead.
