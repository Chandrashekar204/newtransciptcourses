A host refers to any hardware device capable of participating in network communication. Networking can be involved even when only one machine is involved.

Don't forget that a machine today may in fact be a virtual machine, so I'll stop saying machine. A common networking configuration that you've probably heard of is client server. This means that one or more hosts on the network are acting as servers and the other hosts are clients that connect too the server. At a high level that's how the Internet operates. Clients are end-user devices or applications that request services or resources from servers.

A laptop using a browser, a mobile device, or a gaming console are all examples of clients. They initiate communication with the servers and rely on them to fulfill specific requests. Servers are usually powerful computers or software applications that provide services or resources to clients. They listen for incoming requests from clients, process those requests, and respond with the appropriate data or action. Communication between the user's devices and servers responding to their requests is called the client-server model.

This is a very common networking model used in many different applications, including web applications, email, file sharing and gaming. Web browsing is a classic example where the web browser (the client) sends requests to web servers and the servers respond by sending back web pages, images, or other resources. As I mentioned you can have a client server interaction on the same host. For example the My SQL database comes with software we've been using called My SQL Workbench.

The workbench is the client, and it connects to the My SQL database server on that local host. It could also connect remotely to another server if needed as well. Another example is local web development. It's possible to run a web server on your computer and connect to it using a browser on that same computer. In fact that's often what web developers do when they're working on a website for a client. Clients and servers communicate through several layers of protocols The lowest level is the network layer which uses addresses to facilitate network communication.

On top of this is the data transport layer. Both are managed by protocols which are just sets of rules, conventions and agreements. A network protocol is like the postal service's addressing system ensuring a package or letter can be addressed and its destination determined. A data transport protocol is like a specific type of delivery system. One type of delivery system may track and ensure the safe delivery of your package. Another simply dumps your letter or package at the address and hopes for the best outcome.

When data arrives at the one physical connection to the network, it gets routed to the target application through a port. Each application that needs data from the network is assigned a port. This includes clients connecting to a server that's on the same machine. When data arrives, the port number is used to route the data for the specific application that's waiting for it. A port number is a positive integer between 0 and 65535. Some port numbers are reserved, some are simply well known, and some are actually registered.

If you're interested you can find a list on wikipedia, showing which port falls into any of those categories. Every host connected to the Internet also has a unique IP address, including yours. IPv4 stands for Internet Protocol Version 4 and IPv6 stands for Internet Protocol Version 6. Once upon a time there were only IPv4 addresses. IPv4 uses a 32-bit address scheme that allows for over 4 billion unique addresses. We've got computers, tablets, game consoles, smart TVs, smartphones, smart appliances, and so on, all connected to the Internet, and each device has to have a unique IP address. As a result, four billion IP addresses wasn't really enough, and so IPv6 was born.

This ensures compatibility with older and newer technologies. For example, new routers support IPv6 but if you're hanging onto an older router, it may not. Or your ISP may only provide IPv4 addresses. Or you just have it configured that way. Computers on a network which includes the internet communicate with each other using a special data transfer layer.

The data transfer layer provides different protocols for transferring data. In this section, I'll cover the TCP and UDP protocols. There are others, but these two protocols which have been around since 1974 and 1980 as shown on this slide, are still widely used by client server applications. The biggest difference between TCP and UDP is that TCP is connection oriented, meaning it establishes and maintains a connection between hosts. UDP is connectionless, it sends data but doesn't wait to see if the delivery was successful and won't listen for a response.

TCP is highly reliable because it guarantees ordered delivery of data. UDP is less reliable with no real guarantee of delivery or order. Data transmitted with TCP is done in a continuous stream-like fashion over the established connection. Data transmitted by UDP is done with independent unrelated data packets. TCP provides extensive error checking with retransmissions compared to UDP which has no error checking. With UDP, lost data or packets, are simply dropped TCP incurs a higher overhead and is slower due to connection management and error checking.

TCP is used when you need reliable data transfers like web browsing, email, and file downloads. UDP is used when speed is more important than reliability so in online gaming, streaming media and for real time data feeds for example. TCP IP describes both the networking and data transport layers used. It refers to using the TCP protocol for transferring data over a network of IP addresses. Two applications running on the same host can still use TCP IP to communicate with each other.

When the client and server are on the same host usually the IP address one two seven dot zero dot zero dot one, which is also referred to as the local host is used to identify the host.
