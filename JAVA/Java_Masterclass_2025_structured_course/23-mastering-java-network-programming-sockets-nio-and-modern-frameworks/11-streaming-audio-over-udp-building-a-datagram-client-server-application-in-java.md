Kind: captions Language: en In the last video we left off with a very simple UDP client server app working. Before I add the audio part, let me just compare the TCP and UDP processes for a minute. For TCP, we use either a server socket for the server or just a simple socket for the client. For UDP, both the server and client use a datagram socket. For TCP, the accept method on the server and the connect method on the client establishes a virtual connection between them.

This ensures reliable in-order delivery of data with error detection and congestion control. For UDP, there is no handshake, so no accept or connect happens. For TCP, data is exchanged linearly via the sockets input and output streams. For UDP, data is exchanged independently of other data with datagram packets, so the exchanges are unreliable and unordered. For TCP, the server events are bind and accept. They communicate by reading and writing to the socket input and output streams.

The TCP client needs to first connect, but after that it again use its socket input and output streams to exchange data. For UDP, the server still needs to bind to a port, but then it can receive or send packets to any client, by just including the client's address information in the packet. In other words a UDP server could broadcast its packets to many clients. The UDP client similarly sends packets that way but can receive packets addressed to it.
