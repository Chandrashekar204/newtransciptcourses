So the positioning of the catch block doesn't matter, if you want to kind of cancel the promise chain, you have to move it to the end of all your then blocks because only then you make sure that if one of them rejects, the other ones are skipped and you make it into catch. If you wanted to crash entirely, you can always force that by moving catch to the end of course. If you have catch somewhere in the middle, then the promise chain continues after catch and of course, you could have another catch in there to handle an error in here because if this rejects for some reason, this catch block which came before it will not do anything, you would need a new catch block or a new second argument to handle any errors here or in other then blocks thereafter.

So this is error handling and how promise chaining works with errors, really important to understand that, gives you a lot of power and all the flexibility you need to write great applications which also can deal with errors in a graceful way.
