Instructor: The next method that we can use to configure our custom filters is addFilterAt(). So this method is somewhat tricky compared to addFilterBefore() and addFilterAfter(). We know what exactly is going to happen when we're using the other two methods. But in the scenario of addFilterAt() method, it is going to be executed at the same portion of Spring Security filter. If I configure my custom filter with the help of addFilterAt() method, then my custom filter is also going to have the same order like BasicAuthenticationFilter.

But here, you need to be aware about two important points. So this method will not replace the filter already present at the same order, so don't be under the assumption that the BasicAuthenticationFilter will be replaced by my custom filter. This is never going to happen. Instead, both the filters, they are going to be executed, but Spring Security, it is not going to guarantee which filter is going to be executed first. That's why whenever you are defining your custom filter with the help of addFilterAt() method, please make sure there is a possibility that your filter may get executed before the BasicAuthenticationFilter.

So here, I just mentioned the BasicAuthenticationFilter as an example, but like I said before, you should be able to configure any Spring Security filter other than BasicAuthenticationFilter. In general, I don't recommend you using these addFilterAt() method because we never know which of these filters are going to be executed first. Unless your business logic does not depend on the order of the execution of these filters, which are configured at the same order value, then you can happily use it.

Otherwise, feel free to use the addFilterBefore() and addFilterAfter() method.
